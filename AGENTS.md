# Clinic-App project instructions

## Start of every project session

- Remind the user to read [the implementation plan](docs/5_implementation_plan.md) and [the API design](docs/6_api_design.md). Include clickable links in the opening update. Give this reminder once per session, without requiring confirmation or blocking work.
- Read both documents and [the session handoff](docs/session_handoff.md) before making project changes. Read relevant ADRs for the task.
- Treat the roadmap and API contract as proposed designs, not implemented capabilities. Check the code and current user instructions before acting. Discuss material departures and keep the docs aligned with agreed changes.

## Continuity

- Use `docs/session_handoff.md` to understand prior work, decisions, assumptions, and remaining tasks. Update it after meaningful project work so the next session can continue accurately.
- Preserve existing uncommitted changes. Do not assume earlier changes were committed, tested, or implemented merely because they appear in a plan.
